# Prompt: Create FVSlope (Flow Vector Slope) Tool

You are in the WhiteboxTools fork (WEPPcloud variant).

## Goal

Create a new tool in the `hydro_analysis` toolbox named `FVSlope` (Flow Vector Slope).

This tool calculates slope gradient **in the direction of flow** for each grid cell, as opposed to the standard `Slope` tool which calculates maximum terrain gradient. This approach is used by TOPAZ and is more appropriate for channel/flowpath hydraulic modeling in WEPP, where the along-channel gradient determines flow velocity and shear stress rather than cross-channel valley wall slopes.

## Background

The standard WhiteboxTools `slope()` function uses Horn's method to calculate the maximum terrain gradient from a 3x3 or 5x5 neighborhood. In channel/valley locations, this often returns the steep cross-channel slope to valley walls rather than the gentler along-channel gradient.

For watershed erosion modeling (WEPP), channel hydraulics require the slope **in the direction water flows**, not the steepest terrain slope. TOPAZ calculates this by:
1. Looking up the D8 flow direction for each cell
2. Finding the downstream neighbor cell
3. Computing slope as: `(elevation_here - elevation_downstream) / distance`

This produces slopes that are typically 40-65% lower in channel locations compared to Horn's method, which is physically correct for channel flow routing.

## Inputs

- `--dem` (required): Input raster DEM file. The DEM from which elevations are read.
- `--d8_pntr` (required): Input D8 pointer (flow direction) raster. Must be generated by the `D8Pointer` tool.
- `--output` (required): Output raster file for the flow vector slope.
- `--esri_pntr` (optional, boolean, default=false): If true, interpret the D8 pointer using ESRI's flow direction convention (powers of 2: 1,2,4,8,16,32,64,128). If false, use WhiteboxTools convention (0-7 clockwise from north).
- `--zfactor` (optional, float): Multiplier for when the vertical and horizontal units differ (e.g., elevations in feet, horizontal in meters).
- `--units` (optional, default="degrees"): Units for output raster. Options: `"degrees"`, `"radians"`, `"percent"`, `"ratio"`.

## Behaviour

1. **Read inputs**: Load the DEM and D8 pointer rasters. Validate they have matching dimensions.

2. **For each cell**:
   - Skip if DEM value is nodata
   - Get the D8 flow direction value
   - Decode to row/column offset for downstream neighbor:
     - WhiteboxTools convention: 0=E, 1=NE, 2=N, 3=NW, 4=W, 5=SW, 6=S, 7=SE (clockwise from east)
     - ESRI convention: 1=E, 2=SE, 4=S, 8=SW, 16=W, 32=NW, 64=N, 128=NE (powers of 2)
   - Calculate distance to downstream cell:
     - Cardinal neighbors (N,S,E,W): `distance = cell_size`
     - Diagonal neighbors: `distance = cell_size * sqrt(2)`
   - Get elevation of downstream cell (if valid)
   - Calculate slope: `(z_here - z_downstream) / distance`
   - Apply zfactor if provided: multiply elevations before differencing
   - Convert to requested units:
     - `ratio`: slope as-is (rise/run)
     - `percent`: slope × 100
     - `degrees`: atan(slope) converted to degrees
     - `radians`: atan(slope)
   - If downstream cell is nodata or outside grid, set output to nodata

3. **Handle edge cases**:
   - Cells at grid boundary pointing outward: set to nodata
   - Flat areas (zero slope): output 0
   - Negative slopes (flow direction points uphill): output 0 or nodata (match TOPAZ behavior of setting to -1/nodata)

4. **Geographic coordinates**: For DEMs in lat/lon, calculate actual ground distance to downstream cell using haversine or vincenty formula (similar to existing `Slope` tool).

## Outputs

- Raster output with slope values in the specified units
- NoData where input DEM is nodata or downstream cell is invalid
- Metadata entries for:
  - Tool name and input files
  - Slope units
  - Whether ESRI pointer convention was used
  - Elapsed time

## D8 Direction Encoding Reference

### WhiteboxTools convention (default):
```
Direction:  0    1    2    3    4    5    6    7
Meaning:    E   NE    N   NW    W   SW    S   SE
Row delta:  0   -1   -1   -1    0    1    1    1
Col delta:  1    1    0   -1   -1   -1    0    1
```

### ESRI convention (--esri_pntr):
```
Direction:   1    2    4    8   16   32   64  128
Meaning:     E   SE    S   SW    W   NW    N   NE
Row delta:   0    1    1    1    0   -1   -1   -1
Col delta:   1    1    0   -1   -1   -1    0    1
```

## Python Wrapper

Add to `whitebox_tools.py`:

```python
def fvslope(self, dem, d8_pntr, output, esri_pntr=False, zfactor=None, units="degrees", callback=None):
    """Calculates slope gradient in the direction of flow (flow vector slope).

    Unlike the standard slope tool which calculates maximum terrain gradient,
    this tool calculates slope along the D8 flow direction. This is more
    appropriate for channel hydraulic modeling where along-channel gradient
    determines flow velocity and erosion, not cross-channel valley wall slopes.

    Keyword arguments:

    dem -- Input raster DEM file.
    d8_pntr -- Input D8 pointer (flow direction) raster.
    output -- Output raster file.
    esri_pntr -- Use ESRI's D8 flow direction convention (powers of 2).
    zfactor -- Optional multiplier for when vertical and horizontal units differ.
    units -- Units of output: 'degrees', 'radians', 'percent', or 'ratio'.
    callback -- Custom function for handling tool text outputs.
    """
    args = []
    args.append("--dem='{}'".format(dem))
    args.append("--d8_pntr='{}'".format(d8_pntr))
    args.append("--output='{}'".format(output))
    if esri_pntr:
        args.append("--esri_pntr")
    if zfactor is not None:
        args.append("--zfactor={}".format(zfactor))
    args.append("--units={}".format(units))
    return self.run_tool('fvslope', args, callback)
```
